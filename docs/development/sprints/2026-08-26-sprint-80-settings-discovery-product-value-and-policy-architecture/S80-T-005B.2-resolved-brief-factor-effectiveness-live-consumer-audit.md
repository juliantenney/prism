## 0. Evidence standard

**OBS** = read directly in live code/pack (file+line cited) · **TEST** = existing deterministic test proof · **INF** = inference, labelled as such · **UNPROVEN_BEHAVIOURALLY** = static wiring plausible but no deterministic test exists.

## 1. Executive conclusion

**Of 44 resolved brief keys, 25 have a proven current effect and 17 have none. Only 6 produce proven model-visible text.**

Four structural findings explain almost every dead chain:

1. **The Create-time bake cannot see any brief factor.** `buildSeededStepPromptForWorkflowStep` — which produces `override_prompt_body` — hardcodes `var selectedOptions = []` (**OBS** `app.js:5373`) and strips the param block from notes (`5381`). It never reads `step.prompt_bindings.selectedOptions`, which Create populated three lines earlier (`35463–35467`). The fallback builder never reads `ctx.workflowOutputSpec`. **No resolved factor value reaches a baked prompt body.**

2. **`[PRISM_STEP_PARAMS]` has no reachable route to a model at all.** The block is stripped at every notes-to-prompt boundary (`33786` Copy, `33344` GAM copy, `34367`, `5381`, `6078`). The one builder that would have emitted params, `buildPromptFactoryWorkflowContextText`, has exactly one caller — inside a block that is **provably unreachable**: `handleStartRefinement` returns early at `27107–27109` when `state.promptFactoryWorkflowContext` is set, and the calling block at `27126` requires that same truthy value (**OBS**). The remaining reader, `collectWorkflowStepPromptOptionSelections` at `6214`, feeds only `isWorkflowStepLowFrictionMode`, a UI boolean. **This corrects my own interim finding**: there is no Studio prompt route either. `STUDIO_ONLY_EFFECTIVE` survives only as UI-panel inheritance (2 factors), not as prompt text.

3. **The genuinely live model-visible route bypasses step params entirely.** `applyWorkflowStepRuntimePromptAugmentations` (`15990`) reads `wf.workflowBriefResolution.resolvedFactors` **directly** via `resolvePedagogicCognitionBriefContextForPrompt` (`8234`). Only a handful of factors are read by *value*: `delivery_context`/`delivery_mode` (`7613`, `8271`, `15708`) and `page_profile` (`11625`).

4. **Topology is where brief factors actually earn their keep**, via pack `triggerRules` using `whenResolvedFactorsInclude` → `include`/`exclude` (**OBS** pack `127–226`), evaluated at `app.js:23283–23293`. 17 keys have proven topology effects, many test-backed.

**Product consequence:** the old Settings surface was largely a display layer over values with no consumer. That is now demonstrated rather than suspected — `formatWorkflowSettingsParamDisplayValue` (`3554–3562`) renders a friendly "yes"/"no" for `include_examples`, a value no prompt builder reads.

## 7. Step-param dead ends

**Every** stepParam projection is a dead end for prompts. Written at `35448–35461`, mirrored at `35464`, read by nothing that builds a model prompt.

- **Design Assessment**: `coverage_scope`, `difficulty_profile`, `assessment_cadence`, `total_items`, `activity_type` — the baked body is discarded and replaced by a six-line fixed brief (`33810–33812`, `11127–11136`).
- **Generate Assessment Items**: `question_style_mix`, `difficulty_profile`, `number_of_items`, `response_formats`, `composition_mode` — stored prompt voided (`31432–31439`).
- **Design Page**: `include_answers`, `include_feedback_guidance`, `feedback_display`, `include_examples`, `include_practice_tasks` — template has no `{{option:…}}` tokens for them.
- **Learning Sequence**: `duration_minutes`, `sequencing_granularity`, `sequencing_style`.
- **Design Feedback**: `feedback_required`.
- **Learning Outcomes**: `learnerLevel`, `numberOfOutcomes`, `cognitiveEmphasis`, `scope`.

**Ordering bug (OBS).** `buildSeededStepPromptForWorkflowStep` receives `constraints: scopeAndConstraints` at `35477`, but `scopeAndConstraintsCombined` — the version containing `workflowConstraintPatch` — is not computed until `35502`. Mapped constraints are appended to the workflow record *after* every step body has been baked.
