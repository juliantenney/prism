## 1. Executive conclusion

**The resolved brief model is larger and less declarative than the pack suggests.** Three findings matter more than the raw count:

1. **The pack is not the complete factor vocabulary.** The LD pack declares **28** factors, but `resolveWorkflowBriefFactors` also writes **8 undeclared keys** through an explicit hardcoded passthrough list (**OBS** `app.js:19509–19518`), and **5 more** cognition booleans are merged into `optionalFactors` **by code, conditionally**, only when the config carries `intentClasses.assessment_pack` (**OBS** `app.js:7497–7501`). Plus one backward-compatibility alias. **Total distinct keys that can appear in `resolvedFactors`: 42.**

2. **`resolvedSources` provenance is genuinely 4-valued but `"default"` is overloaded.** After the declared-factor loop assigns sources, two mutators run — `deriveAssessmentSemanticFactors` then `reconcileWorkflowBriefPedagogicFactors` (**OBS** `app.js:19539–19540`) — and a fallback loop then labels *anything still unattributed* as `"default"` (**OBS** `app.js:19541–19547`). So `"default"` means **either** "pack-declared default" **or** "deterministic derived consequence PRISM cannot attribute". **Provenance is lost precisely where a parameter layer would most need it.**

3. **Factor vocabulary drifts, and frozen `briefConfig` preserves the old vocabulary.** The 5 cognition booleans appear as `optionalFactors` inside the fixture's **frozen** `briefConfig` (**OBS** `tests/fixtures/educational-psychology-post-s68/workflow.json:480–513`) and in its `resolvedSources`, yet they are **absent from the live LD pack** (**OBS** — grep for `cognitive_engagement_required` across `domains/` matches only the *research* pack). Old workflows therefore carry a factor vocabulary the live pack no longer declares.

**For Topic specifically**, this task resolves the open question from T-005B: `topic` is a **required, free-text, single-purpose** factor with **one declared alias** (`workshop_subject`) and no enum entanglement. It is the cleanest candidate in the entire 42-key model.

**No parameter set is chosen. T-005C and T-006 are not started.**

## 8. Provenance model

**`resolvedSources` semantics (OBS `app.js:19476–19547`):** a flat map `factorId → source`, with exactly four values.

| Value | True meaning |
| --- | --- |
| `explicit` | Present in the explicit map — Create control, product seed, or explicit brief field |
| `elicited` | Answered in follow-up Q&A |
| `inferred` | AI proposal or pack `inferenceRule` (**the two are not distinguished**) |
| `default` | Pack default **or** any unattributed derived value (**overloaded**) |

**Four provenance-loss cases, all OBS:**

1. **`inferred` conflates AI with deterministic rules.** `inferredValues = Object.assign({}, aiFactors, ruleInferredValues)` (`~21797`) merges both into one map before resolution. A rule-derived `learner_level: "undergraduate"` and an AI guess are indistinguishable afterwards.
2. **`default` conflates pack default with derived consequence.** The fallback loop (`19541–19547`) labels anything left over as `default`, *after* `deriveAssessmentSemanticFactors` and `reconcileWorkflowBriefPedagogicFactors` have written new keys. ## 17. Important architectural observations

1. **The factor model is not fully declarative.** 13 of 42 keys (8 passthrough + 5 conditional cognition) exist in code, not in the pack. Any typed parameter layer that reads only pack declarations would silently miss them.
2. **The factor vocabulary is itself conditional** on `intentClasses.assessment_pack` (D10).
3. **Frozen `briefConfig` is a vocabulary snapshot.** Old workflows carry factor definitions the live pack has dropped — a versioning issue T-005 §9 flagged in the abstract and this task confirms concretely.
4. **`"default"` is an overloaded provenance value**, conflating pack defaults with derived consequences (§8 case 2).
5. **The product seed is laundered into `explicit`** (§8 case 3), which currently makes "author chose" indistinguishable from "product kind implied".
6. **Relevance predicates gate inference and defaults but not explicit/elicited values** (`app.js:19483–19495`) — so an out-of-context factor can still be resolved if supplied directly.
7. **High-impact factors already have a confirmation gate** (`topic`, `design_scope` et al., `app.js:20742–20750`). This is a pre-existing precedent for treating some values as needing author affirmation.
8. **Assessment dominates the model** (17 of 42 keys) and is the least declarative part — correctly deferred by this task's scope.
9. **Two domains, two conventions.** Research declares `audience` and `objective_type`; LD declares neither. There is no shared core factor vocabulary across domains beyond `input_strategy`, `topic`, and `page_profile`.
