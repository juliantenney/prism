## 5. Task–material sufficiency failure (working hypothesis)

**Working concept (not yet a schema/rule):**

> **TASK-MATERIAL CLOSURE / TASK-MATERIAL SUFFICIENCY** — Every substantive learner action requiring an input should have an explicit corresponding material obligation, with sufficient quantity, variation, and specificity for the learner to perform the task.

### Trace examples (Lagrangian)

| Activity | Observation |
| -------- | ----------- |
| **A2** | Asked learners to work with new / practice examples without clearly specifying a corresponding independent-practice material obligation. **GAM happened to compensate** by generating additional problems. |
| **A3** | Asked learners to independently solve a new optimisation problem without DLA explicitly requiring that new problem as a material. |
| **A4** | Asked learners to complete short lambda-value interpretation exercises, but **no** corresponding values / cases / exercises were commissioned. GAM did not provide them. Benchmark classified this as a **Major** production defect. |

**Architectural implication:** A final score that depends on GAM luckily inferring a missing DLA obligation is **not** proof that EP → DLA → GAM contracts are correct.

**Do not implement** task-material closure as a new schema in pack opening. It is a Sprint 76 **investigation / design hypothesis**.

## 9. DLA size anomaly (first-class investigation item)

Current DLA prompt size has been observed at approximately **72,000 characters** — more than double its size around the previous DLA audit / rationalisation.

Documented prior rationalised scale: Sprint 56 DLA **core ~31,932** (2026-07-01). Sprint 71 results sit after that rationalisation and before Sprint 72 evidence-centred additions; the **assembled Sprint 71 DLA size is not measured in the review files**.

We have **not** knowingly introduced anything that justifies a doubling of DLA’s responsibility or prompt size.

**Do not assume 72k is legitimate.**

Sprint 76 Task 1 must **account for the growth as a historical delta**, not merely classify the current prompt. Where repository history permits, reconstruct:

**known-good / previously rationalised DLA → subsequent changes/additions → current ~72k assembled DLA.**

Possible causes to investigate (none assumed true):

- duplicated prompt fragments;  
- repeated assembly / injection;  
- superseded instructions retained alongside replacements;  
- multiple versions of the same contract;  
- evidence machinery duplicated across layers;  
- examples / schema / guidance unintentionally repeated;  
- conditional instructions injected universally;  
- legitimate but accumulated additions never re-rationalised.

**Goal:** one clear authoritative statement of each DLA responsibility — no unnecessary competing or duplicated instruction.  
**Do not** set an arbitrary character target.

Prior art for prompt rationalisation methodology includes Sprint 55 / 56 DLA audits (historical reference only — not a claim that current size is already explained).

## 10. Evidence injection under review

Recently introduced DLA **evidence-injection** machinery is explicitly subject to review.

**Observed facts:** a live validator **false positive** occurred; ordinary **procedural mathematical task material** was interpreted as **evidence-dependent**.

**Audit question (not a settled finding):** evidence machinery **may conflate or insufficiently distinguish** material requirement, provenance/authenticity, and epistemic function; observed semantic friction makes this a **first-class audit question**.

### Working distinctions (not final schema)

| Concept | Question | Notes |
| ------- | -------- | ----- |
| **1. Material requirement** | What must exist for the learner to perform the task? | Optimisation problem, dataset, worked example, source extract, scenario, equation, case, image, practice questions, … |
| **2. Provenance / authenticity** | May PRISM generate/simulate, or must material be authentic/external? | Generated/simulated material is legitimate for many tasks (math practice, fictional cases, synthetic datasets, hypothetical scenarios). Authentic material matters when learning depends on a specific real source (e.g. institutional policy, a copyrighted poem under study). |
| **3. Epistemic function** | Is the learner using the material as **evidence** to infer, interpret, evaluate, compare, or justify a substantive conclusion? | Evidence is potentially a **type/function** of learner material — not a synonym for all supplied task inputs. |

Do **not** implement this model at pack opening. It is a framework for auditing existing DLA evidence machinery.
